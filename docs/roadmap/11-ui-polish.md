# 阶段 11：研究台 UI 全面优化

状态：`COMPLETE`

完成日期：2026-07-31

## 目标

在不改变行情数据边界、认证方式和只读行为的前提下，统一研究台的视觉语言与交互反馈，让用户在桌面和手机上都能更快完成“看环境 → 看候选 → 查持仓 → 深入个股”的工作流。

## 范围

- 重构共享页面壳层：导航层级、当前页反馈、移动端导航、主题切换、焦点样式和页面状态。
- 建立可复用的颜色、间距、圆角、阴影、排版和动效设计令牌，支持深色/浅色主题和减少动效偏好。
- 优化总览、全球市场、荐股研究、自助选股、股票详情和系统状态页面的信息密度与空状态表达。
- 保持服务端渲染、SQLite 只读查询、HTTP 认证、外部行情不进入 Web 请求的边界不变。

## 非目标

- 不修改评分算法、投资组合数据模型或任何行情采集逻辑。
- 不新增交易、持仓编辑或外部 API。
- 不引入前端构建链；继续使用 Jinja2、原生 CSS 和必要的渐进增强脚本。

## 设计决策

- 以“工作台”而非营销 Hero 为视觉中心：首屏突出状态、候选和行动入口。
- 使用低饱和深色视觉基线，首次访问尊重系统的明/暗偏好，提供轻量主题切换；主题只保存在当前浏览器，不影响服务端数据。
- 导航在桌面采用带当前状态的胶囊式分组，在窄屏变为可横向滚动的触控条；所有触控目标至少 44px 高。
- 使用系统字体、明确的数字字形、正负涨跌语义色和统一状态徽章，避免仅依赖颜色传递信息。
- 动效只用于状态反馈和层级进入，遵守 `prefers-reduced-motion`；不阻塞输入、不依赖外部 JS 库。
- 所有页面保留表格/文字可读性，网络或图表依赖失败时仍能完成核心阅读。

## 数据/API 变化

无。仅增加模板语义标记、静态样式和浏览器端渐进增强脚本。

## 风险与处理

- 主题切换可能导致旧浏览器缓存样式：增加静态资源版本号并使用 CSS 变量集中管理。
- 移动端横向导航可能遮挡内容：采用滚动容器、焦点滚动和安全区内边距。
- 动态脚本失败不能影响页面：所有行为均为可选增强，默认 HTML 仍可用。

## 验收标准

- 六个业务页面共享一致的导航、标题、卡片、状态和表单视觉语言。
- 1440×900 与 390×844 下无横向溢出；键盘可见焦点、对比度和减少动效偏好可用。
- 首页首屏保留候选优先级，指标/市场带不过度抢占垂直空间；空数据状态清晰且不塌陷。
- 主题切换、当前导航、返回顶部/刷新提示等渐进增强在脚本不可用时不影响核心内容。
- `ruff check .`、全量单测、`compileall`、模板渲染测试和本地认证页面回归通过。

# 阶段 7：个人决策反馈闭环

状态：`PLANNED`

## 目标

让系统从“给出同一套技术候选”升级为“理解本人的持仓、偏好和历史决策结果”。差异化不依靠复制同花顺的资讯、盘口和社区，而是持续提高本人每次决策的可解释性、一致性和复盘质量。

## 个性化护城河

1. **建议记忆**：保存每次候选当时的指标、理由、反对理由和失效位，避免事后用新数据改写旧判断。
2. **本人决定**：允许记录“买入、继续观察、忽略”及一句话原因，不自动交易。
3. **结果校准**：在后续 5/20/60 个交易日计算收益、最大有利/不利波动和是否先触发失效位，按本人真实决策校准阈值。
4. **持仓感知**：候选排序考虑当前成本、单股仓位、行业/风格集中度、相关性和剩余风险预算；即使个股分高，若会加重集中风险也要降级。
5. **反事实复盘**：同时展示“买了会怎样”和“为什么当时没选”，区分策略问题、执行问题和纪律带来的避险。
6. **低噪声提醒**：只提醒状态变化、接近失效位和需要本人决策的事项，不重复推送没有变化的行情信息。

## 范围

- 新增不可回写的候选快照表、本人决策日志和后续表现表。
- 新增“今日待决策”“决策日志”“周度复盘”和“持仓风险”页面。
- 第一版个性化只采用透明规则和分组统计，不用小样本训练黑盒模型。
- 财务质量、估值和行业标签只有在数据源稳定、字段口径可测试后才接入。

## 非目标

- 不自动下单，不替本人确认交易。
- 不做社交荐股、内容社区或面向公众的统一排行榜。
- 不用单次盈亏判断建议好坏；以足够样本、固定观察窗口和风险调整结果评估。

## 数据设计原则

- 推荐快照创建后不可修改，只能新增后续评价，保证审计性。
- 交易日窗口由本地交易日数据决定，禁止自然日近似。
- 记录模型版本、研究范围和数据日期，策略升级前后分开统计。
- 决策文本和结果仅保存在个人服务器，不发送到第三方分析服务。

## 验收标准

- 任一历史建议可重现当时看到的证据、反对理由和失效位。
- 能按股票、建议状态、本人决定、模型版本和日期筛选决策日志。
- 自动补齐 5/20/60 日结果，明确尚未成熟的观察窗口。
- 周报能分离“策略命中”“本人执行”“风险纪律”三个维度。
- 候选因已有持仓暴露被降级时，页面必须解释具体原因。
- 数据库迁移、离线测试、备份恢复和桌面/手机验证全部通过。

# 阶段 6：个人荐股与自助选股台

状态：`COMPLETE`

## 问题

当前 Web 只展示持仓、关注池和系统状态，属于运维型只读仪表盘：浏览器原生 Basic Auth 登录生硬，候选范围过窄，没有荐股排序、反对理由或可组合筛选条件，也没有体现个人研究系统相对同花顺等综合平台的差异。

## 产品定位

不与综合行情平台竞争资讯数量、盘口深度和社区热度，而是成为一个只服务本人的“决策质量系统”：

1. 每个候选都解释入选原因、风险、观察失效位和数据时间，不输出无依据的“必涨”。
2. 选股规则由本人组合并可复现，结果与同一套回测/实盘评分口径连接。
3. 结合真实持仓成本、风险预算、关注偏好和已有暴露，而不是给所有用户同一张榜单。
4. 后续记录每次建议、当时证据、本人决定和事后收益，用个人历史校准阈值，形成同花顺难以复制的反馈闭环。

## 本阶段范围

### A. 登录体验

- 新增中文登录页，成功后签发 HMAC 签名、`HttpOnly`、`SameSite=Lax` 的会话 Cookie。
- 默认“30 天内保持登录”，支持退出；Cookie 在 HTTPS 下设置 `Secure`。
- 继续接受 HTTP Basic 作为脚本兼容入口，但普通页面未登录时跳转登录页，不再弹浏览器原生认证框。
- 用户名、密码和独立会话密钥仍只来自服务器权限 `0600` 的环境文件。

### B. 可解释荐股榜

- 只读 SQLite 中已有的 19 股研究样本，不由 Web 请求外部行情。
- 使用 V2 技术评分、20 日趋势/动量、成交量变化、波动率、60 日回撤和 20 日低点生成候选卡。
- 明确区分“重点研究、进入观察、耐心等待、风险回避”，同时给出理由、风险标签和观察失效位。
- 实时快照存在时用于关注/持仓展示；跨股票排行统一使用同一交易日的本地 qfq 日线，避免时间错位。
- V3 因样本外未通过而不用于推荐，不把研究候选包装成已验证策略。

### C. 自助选股器

- 支持最低评分、20 日最低动量、最大年化波动率、是否站上 MA20、结果数量等组合条件。
- 筛选全部在本地完成，查询不触发同步、通知或交易。
- 查询参数体现在 URL 中，方便收藏和复现。

### D. 信息架构

- 首页改成“今日行动台”：重点候选、当前风险、关注池和数据新鲜度优先，系统运维信息降级到独立页面。
- 主导航至少包含今日、荐股、自助选股、系统和退出。
- 桌面与手机均可使用，空数据和过期数据必须明确说明。

## 延后但已确定的个性化护城河

1. 决策日志：记录“建议—本人操作—后续 5/20/60 日表现”。
2. 个人校准：按本人偏好和历史命中率调整阈值，而不是训练一个面向所有人的黑盒模型。
3. 持仓感知：行业/风格集中度、相关性、成本线、止损空间和单股风险预算。
4. 反事实复盘：展示当时为什么没选、哪条规则导致错过或避险。
5. 研究提醒：只推送状态变化和需要决策的事项，减少综合平台的信息噪声。

## 数据与接口

- 不新增外部行情调用，不改变自动交易边界。
- 新增 `GET/POST /login`、`POST /logout`。
- 新增 `GET /recommendations` 和 `GET /screener`。
- 推荐和筛选为数据库只读计算；本阶段不新增用户写入表。

## 风险与约束

- “荐股”只能表示研究候选，不构成收益承诺；页面固定展示数据日期、模型版本和风险说明。
- 19 股样本不是全 A 股，页面必须显示覆盖范围，不能称为全市场选股。
- 会话密钥缺失时业务页面失败关闭；登录跳转参数只能是站内路径，防止开放重定向。
- 当前单机内存会话失败计数不会跨重启保留；若公网暴力尝试成为实际问题，再增加持久化限速或 Cloudflare WAF 规则。

## 验收标准

- 普通浏览器通过中文表单登录，勾选保持登录后无需反复输入；退出后旧 Cookie 失效。
- 错误凭据、篡改 Cookie、过期 Cookie和缺失会话密钥均不能访问业务页面。
- 首页出现至少一组可解释候选和清晰的研究范围说明。
- 自助选股条件可组合，结果满足条件且 URL 可复现。
- Web 查询期间没有外部网络请求。
- Ruff、编译检查、全量测试以及桌面/手机浏览器验证通过后才可标记完成。

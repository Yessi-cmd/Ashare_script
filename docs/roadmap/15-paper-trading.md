# 阶段 15：实时模拟盘与实盘对照

状态：`COMPLETE`

完成日期：2026-08-01

## 目标

在单用户研究台中增加一个初始资金 10,000 元的模拟账户。用户可以提交任意 A 股代码的买卖委托，监控进程使用与实盘监控相同的本地实时行情和 V2 技术评分撮合，页面持续展示现金、持仓、盈亏、订单历史以及手工登记实盘的并列对照。

## 范围

- 新增模拟账户、持仓和订单三张 SQLite 表；账户首次访问时以 10,000 元初始化。
- Web 提交市价委托，监控进程在交易时段的下一次行情轮询中撮合；Web 不直接请求外部行情。
- 任意待成交股票和模拟持仓自动加入监控股票池，成交后继续获得实时快照和 V2 评分。
- 买入数量必须为 100 股整数倍；卖出遵守 A 股 T+1，并防止重复委托超卖。
- 成交计入万三佣金（最低 5 元）、双边万分之 0.1 过户费和卖出万分之 5 印花税。
- 页面展示总资产、可用现金、持仓市值、累计收益、持仓浮盈亏、可卖数量、V2 评分、订单状态和手工登记实盘对照。
- 所有写操作使用登录认证、CSRF 校验、POST/Redirect/GET 和客户端委托号幂等保护。

## 非目标

- 不连接券商，不读取真实账户资产，不把手工登记持仓描述为券商同步数据。
- 不做自动策略下单、条件单、限价单、集合竞价、涨跌停或部分成交模拟。
- 不支持融资融券、可转债、ETF 特殊交易规则、港美股或多用户账户。
- 不允许 Web 请求 AKShare、腾讯或其他外部行情接口。
- 不回填历史模拟净值曲线；首版以订单账本和当前持仓估值为准。

## 设计决策

1. Web 只创建待成交订单；`monitor.py` 把待成交代码和现有模拟持仓加入实时抓取集合，并以该轮快照价一次性成交。
2. 金额以整数分存储，避免浮点累计误差；持仓成本包含买入费用，卖出已实现盈亏扣除卖出费用。
3. 同一所有者只有一个模拟账户。配置了 `app.owner_user_id` 时使用该 ID，否则使用本地单用户键 `0`。
4. 买入不预占未知成交金额，待成交单按提交顺序处理；资金不足时明确拒单。卖出在提交时扣除已有待卖数量，防止超卖。
5. 当日买入股数不可卖；下一交易日自动变为可卖。休市、测试模式和过期本地页面请求都不会成交。
6. 模拟持仓只复用 V2 评分和信号阈值，不触发自动买卖，也不改变真实持仓的通知和止损止盈状态。
7. 待成交订单可撤销；已成交、已拒绝或已撤销订单不可重复执行。

## 数据/API 变化

- `database.py` 新增 `paper_accounts`、`paper_positions`、`paper_orders`。
- 新增 `paper_trading.py`，负责账户初始化、委托校验、交易费用、T+1、撮合、估值和实盘对照查询。
- `monitor.py` 读取模拟盘监控集合并处理待成交订单。
- `strategies.py` 为仅属于模拟盘的股票计算同一套 V2 评分，但不产生额外通知。
- `web_app.py` 新增 `/paper`、`POST /paper/orders` 和 `POST /paper/orders/{id}/cancel`。
- 新增 `templates/paper.html`，导航增加“模拟盘”。

## 风险

- 行情轮询是离散快照，成交价不是交易所逐笔价，也不模拟冲击成本和排队。
- 最低佣金对 10,000 元小账户影响明显，用户收益可能显著低于不计成本的研究回测。
- 监控进程停机时订单保持待成交；恢复后只会在交易时段且成功获取该股票报价时处理。
- SQLite 适合当前单用户单监控进程；若未来有多个撮合进程，需要增加数据库级抢单语义。

## 验收标准

- 首次访问得到且只得到一个 10,000 元账户，重复访问不重置资金。
- 任意合法 1-6 位数字代码可进入待成交队列，并自动出现在监控抓取集合。
- 合成行情测试证明买入资金、费用、平均成本、卖出回款、已实现盈亏和 T+1 正确。
- 资金不足、超卖、非整手、重复客户端委托号和休市成交均有确定行为。
- 未认证访问失败，模拟盘 POST 缺少或篡改 CSRF 令牌时返回 403。
- Web 页面在桌面和移动端无重叠，能够完成买入、卖出和撤单。
- `ruff check .`、全量 unittest 和 `python -m compileall -q .` 通过。

## 实施记录

- `database.py` 新增模拟账户、当前持仓和订单账本。现金、成本、价格、成交额和费用都以整数分保存；账户按所有者键幂等初始化为 1,000,000 分。
- `paper_trading.py` 实现任意 1-6 位数字代码、100 股整手、市价委托、客户端委托号幂等、待卖股份占用、T+1、FIFO 撮合、资金不足拒单和撤单。
- 费用采用万三佣金且最低 5 元、双边万分之 0.1 过户费、卖出万分之 5 印花税。10 元买入 100 股扣款 1,005.01 元；次日 11 元全部卖出后账户为 10,089.42 元。
- `monitor.py` 每轮把模拟持仓和待成交代码并入实时抓取集合；全市场模式保留原预筛选候选边界。休市和 `--test` 不撮合，失败时订单保持待成交。
- `strategies.py` 对仅属于模拟盘的代码计算同一套 V2 分数，但不新增通知；Web 展示评分、理由、默认 -5% 止损位和 +10% 止盈位。
- `/paper` 提供账户概览、买入票据、实盘记录对照、持仓、卖出和最近 50 笔订单。写操作使用认证、签名 CSRF、POST/Redirect/GET 和页面内两步确认。
- 移动端将持仓和订单表转换为双列字段记录，核心卖出/撤单无需横向滑动；过期行情快照会明确标记。

## 剩余限制

- 成交仍是监控轮询快照的一次性全成模拟，不处理涨跌停、停牌、排队、部分成交和价格冲击。
- 实盘对照来自项目内手工登记持仓，不是券商资产同步。
- 首版没有历史净值曲线、账户重置和限价/条件委托；订单账本可支持后续增加这些能力。

# 阶段 12：荐股榜密度与扫描效率

状态：`COMPLETE`

完成日期：2026-07-31

## 目标

把荐股研究页从大尺寸双列卡片墙改为真正适合排序、扫描和比较的研究榜单：桌面端一眼看到更多候选，仍保留评分解释、关键因子、反对理由和失效位；手机端保持可读的堆叠布局。

## 范围

- 重构 `templates/recommendations.html` 的候选呈现为排名行/紧凑研究条目。
- 增加排名、评分、状态、关键因子、理由摘要和失效位的明确列关系。
- 为窄屏提供自适应堆叠、触控反馈和不截断文本的布局。
- 保持 `load_recommendations()` 数据、排序、认证和详情链接不变。

## 非目标

- 不修改荐股算法、候选排序、评分阈值或数据源。
- 不删除解释性内容；只调整信息的默认展示层级。
- 不新增前端构建链、外部组件或写入接口。

## 设计决策

- 桌面端采用“每只股票一行”的榜单结构，让排名关系和横向比较优先于装饰性卡片。
- 评分和排名使用稳定的视觉锚点；关键因子采用等宽数字，理由与反对理由保持可扫读的短段落。
- 详细反对理由默认保留在行内，不通过隐藏交互才能获得核心风险信息。
- 通过 CSS grid 在 900px 以下切换为两段布局，560px 以下改为纵向信息块，避免横向滚动。

## 数据/API 变化

无。仅调整服务端模板和静态样式。

## 验收标准

- 桌面端不再以两张超宽卡片占满一行；每个候选独立成行且排名清晰。
- 1440px 及以上宽度可同时看到排名、评分、关键因子、理由和失效位。
- 390px 宽度无横向溢出，候选信息按优先级纵向排列，详情链接与触控区域可用。
- 空候选状态、持仓/关注标记、正负数格式和详情链接保持正确。
- Ruff、全量单测、编译检查、模板渲染和浏览器回归通过。

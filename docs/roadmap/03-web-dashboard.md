# 阶段 3：Web 仪表盘

状态：`COMPLETE`
完成日期：2026-07-18

## 目标

提供适合工作日浏览的个人研究界面，快速查看持仓、信号、图表、回测结果和系统健康状态。

## 技术选择

- FastAPI：HTTP 服务和只读 API。
- Jinja2 + HTMX：服务端页面与轻量交互。
- ECharts：K 线、成交量、指标和收益曲线。
- SQLite WAL：个人规模下共享本地数据。

## 首版实施范围

- 新增 `quote_snapshots` 表，由监控进程在完成评分后批量原子更新；Web 只读该快照和本地日线，不请求 AKShare。
- 首页展示持仓、关注池、最新价、涨跌幅、V2 评分、盈亏和快照新鲜度。
- 股票详情展示本地 K 线和评分理由；图表数据通过只读 JSON API 提供。
- 系统页展示快照时间、日线缓存数量和数据库状态；`/healthz` 仅返回无敏感信息的存活状态。
- 首版使用 HTTP Basic 单用户认证，账号和密码只从 `ASHARE_WEB_USERNAME`、`ASHARE_WEB_PASSWORD` 环境变量读取；未配置时除健康检查外全部拒绝访问。
- 页面默认只读，不提供持仓修改、同步行情、执行研究或触发通知的 HTTP 接口。

## 数据/API 变化

- `quote_snapshots(stock_code PK, name, price, change_pct, volume, score, reason, quote_at)`。
- `GET /`：服务端渲染总览。
- `GET /stocks/{code}`：服务端渲染股票详情。
- `GET /api/stocks/{code}/bars`：最多返回最近 500 根本地日线。
- `GET /system`：本地数据与服务状态。
- `GET /healthz`：免认证、无数据细节的健康检查。

## 风险与处理

- 监控和 Web 同时访问 SQLite：启用 WAL、busy timeout、短事务；快照保存失败只记录日志，不中断告警。
- 快照可能过期：页面按上海时间显示更新时间，超过配置阈值明确标为过期。
- Basic Auth 不能替代传输加密：阶段 4 必须通过 Tailscale 或 Caddy HTTPS 暴露，禁止直接开放 Uvicorn 端口到公网。
- ECharts CDN 不可用时页面仍保留表格和文字数据，不影响核心信息读取。

## 首版页面

1. 总览：大盘状态、持仓盈亏、最新信号、数据更新时间。
2. 持仓与关注池：排序、评分、风险状态。
3. 股票详情：K 线、指标、因子贡献、历史信号。
4. 回测报告：参数、收益曲线、回撤和交易明细。
5. 告警记录：触发、恢复和发送状态。
6. 系统健康：行情延迟、连续失败、数据库和服务状态。

## 安全边界

- Web 不直接调用外部行情接口。
- 默认只读；修改持仓仍通过 Bot，后续再评估 Web 编辑。
- 不把 Bot Token、SMTP 密码或完整配置返回给浏览器。
- 所有页面必须经过身份验证后才能访问。

## 验收标准

- 手机和桌面浏览器均可用。
- 首页读取本地快照，在普通个人服务器上快速响应。
- 数据过期时明确显示，不用旧数据冒充实时数据。
- 页面失败不影响监控与通知进程。

## 延后增强项

- 独立告警事件历史表与筛选页。
- 将 CLI 回测 JSON 持久化后的研究报告列表和收益曲线。
- HTMX 局部刷新；当前首版使用服务端渲染和详情页只读 JSON。

这些增强不阻塞“工作日安全浏览持仓、关注池、行情、评分、K 线和系统新鲜度”的 MVP 目标，后续随研究结果持久化一起增加。

## 实施记录与验证结果

- 新增 `quote_snapshots` 和 `snapshot_store.py`；监控评分完成后原子 upsert，失败只告警日志，不影响通知。
- 新增 `web_app.py`、只读查询层、响应式模板和本地静态样式；提供总览、股票详情、日线 API、系统状态和最小健康检查。
- Basic Auth 默认失败关闭，未配置账号密码时业务页面返回 503；错误凭据返回 401。
- Ruff、编译检查和累计 40 项离线测试通过。
- 真实 Uvicorn 烟雾测试：健康检查 200、未认证 401、认证首页 200；本地认证首页约 17ms。
- 浏览器验证：1440×900 和 390×844 均无横向溢出；股票详情成功绘制 180 根本地 K 线，浏览器控制台无错误。

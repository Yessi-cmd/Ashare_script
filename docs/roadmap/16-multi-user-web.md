# 阶段 16：多用户 Web 账号与数据隔离

状态：`COMPLETE`

## 目标

允许把 Web 研究台分享给朋友使用。每个网页账号拥有独立的登录凭据、持仓、关注池、模拟账户和订单记录；公共行情、日线研究和跨市场快照继续共享，避免重复采集。

## 范围

- 新增网页账号表，与已有 `users` 表建立一对一绑定，复用现有按 `user_id` 隔离的持仓、关注池和模拟盘表。
- 新增安全的 PBKDF2 密码哈希，不再把新用户密码以明文或可逆形式保存。
- 登录会话签名内容包含用户 ID，不能在用户之间互换；保留 HTTP Basic 作为脚本兼容入口。
- 新增邀请码注册页；服务器通过 `ASHARE_WEB_REGISTRATION_CODE` 控制是否开放注册。
- 新增个人数据页，让网页用户维护自己的持仓和关注池，并使用 CSRF 校验保护写操作。
- 首页、荐股标记、模拟盘和订单接口全部使用当前登录用户的数据，不再读取共享环境变量账号的数据。
- 监控进程采集所有网页用户所需的股票代码，并为所有网页用户处理待成交模拟订单；Telegram/钉钉/邮件告警仍只服务配置的单一 owner。
- 兼容已有 `ASHARE_WEB_USERNAME` / `ASHARE_WEB_PASSWORD`：首次使用时自动建立遗留网页账号，避免升级后无法登录。YAML 模式下遗留账号继续读取旧 YAML 股票池。

## 非目标

- 不建设管理员后台、角色/组织/计费、多租户数据库或 OAuth/短信登录。
- 不增加密码找回、邮箱验证、二次认证和社交登录；邀请码是当前的受邀边界。
- 不把公共行情、研究日线或跨市场快照复制到每个用户。
- 不给朋友发送个人告警，也不连接券商或执行真实交易。

## 设计决策

1. `WebUser` 使用已有 `User.user_id` 作为数据归属键。新网页注册先创建带负数 ID 的 `User`，再创建 `WebUser`；负数命名空间避免与正数 Telegram ID 碰撞，因此不需要改写历史持仓表结构。遗留账号继续使用配置 owner 或 0。
2. `WebUser` 只保存登录名、PBKDF2 哈希、创建时间和遗留账号标记；会话仍由服务器端 `ASHARE_WEB_SESSION_SECRET` HMAC 签名，服务端不保存会话状态。
3. 页面依赖返回不可变的当前用户身份，所有个人查询函数接收显式 `user_id`；只有监控兼容路径允许使用配置 owner/YAML 回退。
4. 公共 `QuoteSnapshot` 只保存每个股票一份最新行情。监控收集网页用户股票代码的并集，用户页面只读取自己持仓/关注关系与公共快照的交集。
5. 首次访问模拟盘为当前网页用户创建独立的 10,000 元账户。撮合进程按每个待成交账户分别执行，资金、T+1 和订单幂等规则不变。

## 数据/API 变化

- 新增 `web_users(user_id PK/FK, login_username UNIQUE, password_hash, legacy_env, created_at, updated_at)`。
- `GET/POST /register`：邀请码注册网页账号。
- `GET/POST /login`、`POST /logout`：按账号签发/清除用户会话。
- `GET /account`、`POST/DELETE` 个人持仓与关注池接口：只允许修改当前登录用户的数据。
- 既有 `/`、`/recommendations`、`/screener`、`/paper`、股票详情和只读 API 均按当前用户过滤个人关系；公共研究数据保持共享。
- 监控新增全网页用户股票池采集与多账户模拟订单撮合路径。

## 风险与处理

- 注册接口可能被公开滥用：默认只有配置邀请码后才开放，部署文档要求使用长随机邀请码并定期轮换。
- 旧环境变量账号可能没有数据库用户：首次认证时惰性迁移；不覆盖已有数据库账号密码。
- 旧 YAML 模式没有数据库持仓：遗留账号保留 YAML 回退，新注册账号从空白个人数据开始。
- 多用户增加行情代码数量和 SQLite 写入量：代码按股票去重采集，继续使用 WAL/短事务；超过个人规模时再评估 PostgreSQL。
- 所有用户共享最新行情快照：这不会泄露个人数据，但用户看到的实时快照时间可能受其他用户股票池影响；页面明确区分公共行情与个人关系。

## 验收标准

- 两个注册用户能同时登录，分别看到自己的用户名、持仓、关注池、模拟现金、持仓和订单。
- 用户 A 不能通过修改 URL、表单参数、订单 ID、CSRF 或会话内容读取/修改用户 B 的数据。
- 同一浏览器勾选保持登录后可保持 30 天；退出后旧 Cookie 失效。
- 未配置邀请码时注册被拒绝；错误邀请码、重复用户名、弱密码均被拒绝。
- 旧环境变量账号仍能登录，且旧 owner/YAML 数据不丢失。
- 监控对多个网页用户的待成交订单分别撮合，账户资金和持仓不串户。
- `ruff check .`、全量 unittest、`python -m compileall -q .` 通过；不依赖真实凭据。
